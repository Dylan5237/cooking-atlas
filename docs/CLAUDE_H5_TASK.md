## 直接做

把修订设计落到实际 H5 工程：图鉴叠卡/翻面、照片与缺图、收藏、录入草稿核对、点菜/人数推荐、掌勺者确认、采购状态和完整菜谱图片导出。去掉 Emoji 混搭、旧的通用菜图、空泛标语、伪造的制作次数/拿手菜标签。

仓库 `apps/miniprogram` 已有 `build:h5` 与 Taro/React 页面，优先沿用同一代码基线，补一个方便启动的 `dev:h5`，避免先重写 H5 再重写小程序。现有 Taro 相关依赖版本并不完全一致，请按实际构建修正必要兼容问题即可。复用现有 Node.js / PostgreSQL / 对象存储 / API 和业务引擎，不重新引入 CloudBase、不重做服务端架构。确有必要才另建轻量 H5 入口，不需要写选型报告。

H5 不能假装是微信：登录使用现有可用的浏览器试用/会话方式，不直接调用微信小程序登录；文件选图、图片下载/分享、录音能力按浏览器环境适配，微信方法留给下一阶段。不要为演示开放生产免鉴权接口，也不要把密钥放前端。

真实 API 可用就联调。环境不可用时用明确标注的演示模式跑通页面，模拟数据要能刷新保留；保留 API 接口，不把演示冒充云端成功。语音/模型缺凭据不阻塞主要 UI，但保留输入、错误提示和可用的手动路径。不要为了展示成功把 AI 实际失败变成固定假结果。

图标可以复用修订稿，也可以整套替换为一致风格；组件、CSS、轻量动效和适配细节由你决定。优先让功能和界面一次跑起来，不增加审批、复杂抽象或一套新的工程管理流程。
