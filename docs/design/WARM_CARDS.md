# 暖色卡牌 · 设计修订 v2

**本文件取代上一版设计定稿。执行顺序：修订原型 → Claude 实现并展示 H5 → 用户验收 H5 → WorkBuddy 适配微信小程序。** 先不让两边同时改界面，不重新讨论产品定位。

## 唯一参考与范围

打开 `prototype/warm-cards/index.html`。它保留 B 的叠卡、翻面、收藏编号和扇形菜单，沿用 C 的奶油底、鼠尾草绿、陶土橘。本次修正的是图标、文案与缺图状态，不另起一个视觉方案。桌面三屏是展示板，实际 H5 手机只显示一页。

`refinement.js` / `refinement.css` 是原型的 v2 修订层，加载后才是最终效果；原 `app.js` 只保留演示流程。实现时参考页面结果，不要把这套覆盖脚本搬进应用。源码中的旧句子不是本轮文案标准。

## 1. 图标：统一、圆润，但不装可爱

底部四个图标已提供：菜谱册 / 餐碗 / 采购袋 / 围裙。使用同一尺度的圆润轮廓、少量鼠尾草绿或杏桃填充。导航文字始终保留；图标帮助识别，不独自承担含义。

可直接复用原型 `ICONS` 中修订后的 SVG，也可用同气质的完整图标集替换；**不要混用系统 Emoji、人物剪影、黑白机械线图标与彩色图标**。不要求模仿笔触，不做描边抖动。搜索、关闭、加减、返回等小操作保持常规简洁符号；不要每个按钮都塞图标，不再用装饰性 AI 星星或巨大购物袋填版面。

## 2. 菜图：真实照片优先，缺图要诚实

菜品照片是卡面的主内容，不是功能图标。使用真实成品照，正常矩形照片即可，不要求自动抠图。保持菜品清楚、图片比例稳定，避免过度滤镜和拉伸。

本次原型没有用户真实菜照，**默认明确显示“未上传成品照”**，不再以五张通用插画替代所有菜。可点展示板“试放一张成品照”查看本地照片效果，不会上传。Claude 的 H5 演示可使用来源清楚的样例照片，并在演示模式标明“示例照片”；正式数据没有照片时必须保留缺图状态，不拿别的菜、AI 生成图或 Emoji 假装成品照。旧插画文件留在历史中，不再作为默认封面。

## 3. 文案：内容、动作、状态说清楚

| 位置 | 当前用语 / 规则 |
|---|---|
| 图鉴标题 | 我的料理图鉴；下面显示真实的收录数和收藏数 |
| 下方小卡栏目 | 有收藏显示“我的收藏”，否则显示“已收录菜谱”；不能标题写收藏却放推荐 |
| 菜单标题 | 晚餐“今晚吃什么”，午餐“午餐吃什么” |
| 推荐按钮 | 尚无选择“推荐一桌菜”；已有结果“换一组推荐” |
| 菜单列表 | 掌勺者“待确认菜单”，家人“我想吃这些” |
| 关键按钮 | 录入菜谱 / 下一张 / 提交我的点菜 / 确认菜单 / 复制待购清单 |
| 制作记录 | 有记录显示记录次数，没有记录不补成 1 次；不使用 `count + 1` |
| 家人点菜 | “家人点的菜”；只是请求，不表示全家都喜欢或菜单已确认 |
| 空状态 | 还没有菜谱 / 还没有采购清单，并给出下一步入口 |

删除“再做一次，也很喜欢”“这一桌，大家都喜欢”“抽一桌家的味道”等界面修辞，不增加新口号。拿手菜与收藏不是一个概念：没有独立标记功能就不展示拿手菜数量或印章。用户自己写的心得可以有感情，原样保留；只清理系统文案，不擅自改写用户内容。

## 4. 页面与业务继续沿用

图鉴：首页叠卡 → 翻面配方摘要 → 详情完整步骤；次级卡与全部图鉴入口。菜谱录入仍为照片/文字（现有语音可保留）→ 草稿核对 → 保存。编辑更新原记录。

点菜：人数与午/晚餐 → 家人点菜 → 推荐/手动选择 → 掌勺者确认。扇形卡用于预览，普通列表完成替换、移除和份量调整。新菜建议标“未做过”，不冒充已做菜、不自动入图鉴。

采购：仅使用已确认菜单快照。按每道菜原份量和计划份量换算；区分待购、家中已有、已购买；未知用量不虚构。换推荐不能偷偷改掉已确认采购清单。家人只读、可复制，掌勺者维护。

权限：只有掌勺者录入/编辑菜谱和确认菜单，家人浏览/收藏/点菜。演示角色切换仅在演示模式，不是生产权限机制。

## 5. 尺度与自由度

沿用 `tokens.css`：页面 #FBF8EE、卡面 #FFFDF7、主字 #254B42、次字 #64796C、鼠尾草 #DCEAD9、行动色 #DD765D。标题少量系统衬线，正文保持清晰。卡牌层次轻微旋转，阴影轻，不加金属、霓虹或厚黑边。

组件拆分、图标实现、合理的间距字号与照片裁切、动画轻量降级由 Claude 决定。保留 B 的卡牌辨识度和 C 的色板即可，不要求逐像素还原、不新增设计系统或重构后端。实际 H5 不放假微信胶囊和假手机状态栏。

## 6. H5 验收只看这些

启动工程，而非只再输出原型。给出可访问运行入口与图鉴/点菜/采购真实运行截图。跑一次录入（可演示且明确标识）→ 收藏/点菜 → 确认 → 采购，验证角色边界、真实照片和缺图、刷新持久化、完整 PNG 导出，以及 360/390/430px 无遮挡溢出。

H5 未获得用户确认前不启动小程序视觉移植。后续 WorkBuddy 只做平台 API、授权、导航/安全区和真机兼容，不再重新设计。
